# Mini Coding Agent

一个使用 Python 从零实现的命令行编程智能体。用户提供编程任务和工作目录后，Agent 通过 DeepSeek Tool Calling 决定下一步行动，由本地程序完成文件查看、代码修改、命令执行和结果反馈，并持续迭代直到任务完成或触发终止条件。

项目由 DeepSeek API 客户端、模型—工具循环、上下文管理、本地工具和安全控制等模块组成。`openai` 包负责访问 DeepSeek 的 OpenAI 兼容 API，其余模块共同完成消息维护、工具执行、循环控制和错误处理。

## 主要功能

- DeepSeek 原生 Tool Calling 多轮循环；
- 可跨进程恢复的连续对话和多会话管理；
- 模型文字通过 SSE 实时流式显示；
- 八个本地编程工具；
- 工作目录文件边界和符号链接越界检查；
- 非破坏性的 Git 状态、差异和本地检查点；
- 敏感命令人工确认和高风险命令拦截；
- 默认启用 macOS 系统级文件与网络沙箱；
- 命令超时与输出长度限制；
- 重复工具调用与连续失败保护；
- 超限后由 DeepSeek 生成语义摘要，并提供确定性降级；
- 按工作目录隔离、原子写入的本地会话存储；
- 自动提取、相似度检索和手动管理的本地长期记忆；
- 清晰且不回显敏感参数的终端运行信息；
- 170 个不消耗 API 额度的自动化测试；
- 已通过多次真实 DeepSeek 端到端任务验证。

## 运行原理

```text
用户任务
   ↓
CLI 读取配置、工作目录和运行参数
   ↓
CodingAgent 维护消息历史并请求 DeepSeek
   ↓
模型返回最终文字 ─────────────────────→ 流式显示
   │
   └→ 模型返回 Tool Call
          ↓
      ToolRegistry 解析名称和 JSON 参数
          ↓
      敏感操作是否需要用户确认
          ↓
      本地文件工具或命令工具执行
          ↓
      Tool Result 加入对话历史
          ↓
      上下文检查后进入下一轮模型请求
                                              ↓
                              原子保存会话，用户可继续追加需求
```

模型只生成工具名称和参数，不会直接操作本地电脑。工具是否存在、参数是否合法、路径是否越界、命令能否执行以及何时结束循环，都由本地 Python 程序决定。

## 环境要求

- macOS；
- Python 3.9 或更高版本；
- [`uv`](https://docs.astral.sh/uv/)；
- DeepSeek API Key。

当前命令工具使用 `/bin/zsh`，因此第一版主要面向 macOS。其他操作系统需要替换 shell 路径并重新验证命令行为。

默认 `strict` 命令隔离还要求系统提供 `/usr/bin/sandbox-exec`。当前支持使用 `--sandbox-mode policy` 显式退回启发式命令策略，但该模式不具备操作系统级文件和网络隔离。

## 安装

```bash
git clone https://github.com/CRYEAH6/mini-coding-agent.git
cd mini-coding-agent
uv sync --extra dev
```

`uv` 会在仓库内创建独立的 `.venv`，并根据 `pyproject.toml` 和 `uv.lock` 安装可复现的项目依赖。

## 配置

复制环境变量示例：

```bash
cp .env.example .env
```

只在本地 `.env` 中填写真实 API Key：

```dotenv
DEEPSEEK_API_KEY=your_real_api_key
```

`.env` 已被 Git 忽略。不要把真实 Key 写入代码、README、提交记录或演示视频。

| 环境变量 | 必填 | 默认值 | 作用 |
|---|---:|---|---|
| `DEEPSEEK_API_KEY` | 是 | 无 | DeepSeek API 凭据 |
| `DEEPSEEK_MODEL` | 否 | `deepseek-v4-flash` | 模型名称 |
| `DEEPSEEK_SUMMARY_MODEL` | 否 | 与主模型相同 | 历史语义摘要使用的模型 |
| `DEEPSEEK_BASE_URL` | 否 | `https://api.deepseek.com` | API 地址 |
| `DEEPSEEK_TIMEOUT_SECONDS` | 否 | `60` | 单次 API 请求超时秒数 |
| `DEEPSEEK_MAX_RETRIES` | 否 | `2` | API 客户端重试次数 |
| `DEEPSEEK_MAX_CONTEXT_CHARS` | 否 | `200000` | 消息历史近似字符预算 |
| `MINI_AGENT_SESSION_DIR` | 否 | `~/.mini-coding-agent/sessions` | 自定义本地会话存储根目录 |
| `MINI_AGENT_MEMORY_DIR` | 否 | `~/.mini-coding-agent/memories` | 自定义本地长期记忆存储根目录 |

## 使用方法

在仓库目录中启动 Agent，并通过 `--workspace` 指定可以操作的目标项目：

```bash
uv run mini-agent \
  --workspace /absolute/path/to/target-project
```

启动命令不接受任务正文。程序完成配置检查后进入持续交互模式并显示 `你>`，此时再输入第一项需求。这样可以避免单次模式和交互模式之间的歧义。

一轮任务完成后会再次出现 `你>`，可以围绕同一项目继续追加要求：

```text
你> 实现一个飞机大战游戏
...
[完成] 本轮任务已结束

你> 在现有代码上增加暂停和继续功能
...
[完成] 本轮任务已结束
```

第二轮请求会携带第一轮的用户要求、模型回复、工具调用和执行结果。DeepSeek API 本身不保存会话，完整历史由本地 `CodingAgent` 维护并在每次请求时重新发送。每轮结束后，历史会保存到本地；退出程序并使用相同 `--workspace` 再次启动时，会自动恢复上次的活动会话。

交互命令：

```text
/help              显示交互命令
/new               创建新会话，保留旧会话和项目文件
/sessions          查看当前工作目录的历史会话
/switch 会话ID     切换到指定历史会话
/delete 会话ID     确认后删除指定会话
/remember 内容      手动保存一条长期记忆
/memories           查看当前工作目录的长期记忆
/forget 记忆ID      删除指定长期记忆
/exit              结束会话
/quit              结束会话
```

`/new` 不会删除原会话，只会建立新的空白聊天上下文。新旧会话仍然操作同一个工作目录，并共享该工作目录的长期记忆；旧会话的逐条聊天内容不会自动进入新会话。

也可以使用 Python 模块入口：

```bash
uv run python -m mini_agent \
  --workspace /absolute/path/to/target-project
```

可用参数：

```text
--workspace PATH              Agent 的工作目录，默认是当前目录
--max-steps N                 最大模型调用轮数，默认 20
--allow-dangerous-commands    允许高风险命令进入人工确认流程
--sandbox-mode {strict,policy} 命令隔离模式，默认 strict
```

查看完整帮助：

```bash
uv run mini-agent --help
```

## 终端输出

启动时会显示不含凭据的运行配置：

```text
Mini Coding Agent
模型：deepseek-v4-flash
工作目录：/path/to/target-project
最大步骤：20
上下文预算：200000 字符
摘要模型：deepseek-v4-flash
安全模式：高风险命令默认拦截
命令隔离：macOS 系统沙箱
当前会话：20260829T143052123456Z-a1b2c3d4
已恢复 3 轮历史对话。

[模型 1/20] 正在生成下一步...
[回复] 我先检查项目结构和现有代码。
[工具] read_file（path=src/app.py）
[结果] 成功
[模型 2/20] 正在生成下一步...
[回复] 已定位问题，正在修改并验证……
```

`[回复]` 后的文字不是等待整段生成完才出现，而是随 DeepSeek SSE 数据逐块刷新。工具名称和参数也可能分散在多个响应块中，客户端会先完整拼接工具 ID、名称和 JSON 参数，再交给本地工具层执行。

系统指令要求模型在开始任务和进入新的工作阶段时，用一句简短自然语言说明当前目标与下一步动作。播报只覆盖阶段变化，不逐条复述机械操作，也不展示内部 `reasoning_content`。

安装依赖、访问网络或操作 Git 远程仓库等敏感命令执行前，终端会暂停并显示确认信息：

```text
[需要确认] 执行需授权命令
原因：该命令会安装、卸载或同步 Python 项目依赖。
具体内容：uv add requests
是否允许？[y/N]
```

输入 `y`、`yes`、`是` 或 `允许` 才会执行，直接回车和其他输入均视为拒绝。拒绝结果会作为 Tool Result 返回模型，模型可以调整方案或向用户说明无法继续的原因。

写文件时只显示路径和内容长度，局部替换只显示新旧文本长度，执行命令时只显示程序名称和超时，不回显完整代码或命令参数。每轮结束后会显示模型调用次数、工具执行次数、耗时和上下文压缩次数。

## 会话持久化与管理

默认情况下，会话存放在：

```text
~/.mini-coding-agent/sessions/<工作目录名称-路径哈希>/
```

工作目录的绝对路径会生成独立哈希，因此不同项目的会话不会混在一起。每个会话使用一个 JSON 文件，活动会话使用单独指针记录。会话 ID 由 UTC 时间和随机后缀组成，例如：

```text
20260829T143052123456Z-a1b2c3d4
```

保存内容包括用户消息、模型回复、Tool Call、Tool Result 和上下文压缩摘要。system 指令不会持久化；恢复时始终使用当前程序版本的 system 指令，确保后续升级的工具说明和安全规则能够生效。

会话文件通过“写入临时文件—刷新磁盘—原子替换”流程更新，目录权限设为 `700`，文件权限设为 `600`。如果活动指针或某个会话损坏，启动过程会尝试恢复该工作目录中最近的其他有效会话；无有效记录时创建新会话。

保存前会对常见 `API_KEY`、`sk-...`、Bearer Token、密码和 Secret 格式进行脱敏，但自动识别不能覆盖所有自定义凭据。会话中还可能包含源代码和工具输出，因此不要共享会话目录，也不要主动要求 Agent 读取敏感文件。

`/delete` 会显示会话 ID、标题和轮数，并要求用户明确确认。如果删除的是当前会话，程序会先建立替代会话，确保交互仍可继续。

## 本地工具

| 工具 | 作用 | 主要限制 |
|---|---|---|
| `list_files` | 列出目录的直接子项 | 最多返回 200 项，隐藏 `.git`、`.venv` 和缓存目录 |
| `read_file` | 读取 UTF-8 文本文件 | 单次最多返回 50000 字符 |
| `write_file` | 创建或完整写入文本文件 | 只能写入工作目录内路径 |
| `replace_in_file` | 精确替换已有文本 | 默认要求旧文本唯一匹配 |
| `run_command` | 在隔离环境中执行 zsh 命令 | 默认禁止网络，超时 30 秒、最大 120 秒 |
| `git_status` | 查看分支、修改和最近检查点 | 工作目录必须是 Git 仓库根目录 |
| `git_diff` | 比较当前完整工作区与 Git 基准 | 包含已暂存、未暂存和未跟踪文件 |
| `git_checkpoint` | 保存本地 Git 检查点 | 需要用户确认，不改变当前分支和文件 |

`ToolRegistry` 将以上工具的 JSON Schema 提供给模型，并负责名称查找、JSON 解析、参数分发和异常隔离。非法工具名称或参数会转换为失败的 Tool Result 返回模型，而不是让 Agent 直接崩溃。

## Git 检查点与差异

Agent 可以在较大修改前调用 `git_checkpoint`。用户确认后，程序使用临时 Git 索引把当前完整工作区写成快照提交，并保存到以下内部引用：

```text
refs/mini-agent/checkpoints/20260829T123456123456Z
```

这种检查点与普通 `git commit` 不同：

- 不移动当前分支的 `HEAD`；
- 不修改真实暂存区；
- 不还原、清理或覆盖工作文件；
- 不自动推送到 GitHub；
- 包含已跟踪修改和未被 `.gitignore` 忽略的未跟踪文件。

`git_status` 会显示当前分支、文件状态和最近 10 个 Agent 检查点。`git_diff` 默认比较当前完整工作区与 `HEAD`，也可以传入检查点引用，查看创建检查点之后发生的变化。差异快照同样使用临时索引，因此能够同时覆盖已暂存、未暂存和未跟踪文件。

Git 工具只在 `--workspace` 本身就是仓库根目录时运行。第一版不会自动恢复检查点，以免覆盖用户后来产生的修改；模型可以先读取差异，再通过文件工具进行明确、可检查的调整。

## 循环终止与错误恢复

正常情况下，模型返回不含 Tool Call 的最终文字后任务结束。项目还实现以下保护：

- 最大模型调用轮数默认是 20；
- 第 3 次完全相同的工具调用不再执行，并提示模型调整方案；
- 第 4 次仍然重复时终止任务；
- 工具连续失败第 3 次时发出警告；
- 连续失败第 4 次时终止任务；
- 任意成功工具调用会重置连续失败计数；
- 配置错误、API 错误、上下文超限和用户中断使用不同退出路径。

命令返回非零退出码会作为失败的 Tool Result 交给模型。测试失败通常是修复任务需要的观察信息，因此不会立即终止整个 Agent。

## 上下文管理与语义摘要

每次请求前，Agent 会估算消息历史序列化后的 JSON 字符数。未超过默认 200000 字符预算时，历史保持不变；超过后按以下方式处理：

1. 始终保留 system 指令和当前用户要求；
2. 多轮交互时优先移除最早的完整用户对话轮次；
3. 单轮工具历史仍过长时，保留最近两个完整工具轮次；
4. 将准备移除的完整历史交给摘要模型，生成有界的中文语义摘要；
5. 如果必要信息本身已经超限，则明确终止并提示调整预算。

该策略不会拆散 Tool Call 与对应结果。字符数是确定性的近似预算，不等同于模型的精确 Token 数。历史未超限时不会调用摘要模型，也不会产生额外摘要费用。

摘要请求使用同一个 DeepSeek API Key 和地址，但可通过 `DEEPSEEK_SUMMARY_MODEL` 单独选择更便宜的模型；未配置时使用主模型。摘要请求不携带任何本地工具，也不使用流式输出。输入在本地限制为 100000 字符，并对常见凭据脱敏；输出不超过上下文预算的五分之一，且最多 6000 字符。

摘要模型重点保留用户目标与约束、修改文件和关键代码、技术决策、测试结果、重要错误及解决办法和未完成事项。再次压缩时，已有语义摘要会与新移除的历史合并成一份新摘要，避免摘要无限追加。

如果摘要 API 请求失败、返回空内容、意外返回 Tool Call 或超过长度限制，Agent 会回退到原有的本地确定性摘要，当前编程任务不会因此中断。语义摘要与降级摘要都会随会话持久化；旧版本会话缺少语义摘要字段时仍可正常恢复。

## 长期记忆

长期记忆与单个会话历史分开保存，并按照工作目录隔离。成功完成一轮任务后，Agent 会从用户原话中高精度提取明确表达的用户偏好、项目决策和项目事实，例如“README 要写中文”或“项目使用 Python 3.9”。临时任务和模型生成的推测不会自动写入记忆。

新任务开始前，记忆模块将英文技术词、数字版本和中文连续二元词组转换为本地词元，结合余弦相似度、Jaccard 相似度、子串匹配和类别权重选出最多 5 条相关记忆。检索不调用额外 API，也不依赖向量数据库。结果最多占用 2000 字符，并作为当前轮次的临时系统背景发送给模型，不修改原始用户消息或会话文件。

记忆提示明确规定当前用户要求和真实文件内容优先，因此用户的新决定可以覆盖旧记忆。自动写入采用内容归一化和近似去重；文件使用原子替换、`600` 权限、工作目录归属校验和常见凭据脱敏。用户可通过 `/remember`、`/memories` 和 `/forget` 检查并纠正记忆，避免形成不可见状态。

默认存储位置为：

```text
~/.mini-coding-agent/memories/<工作目录名称-路径哈希>/memory.json
```

## 安全边界

文件工具会解析真实路径，并拒绝：

- 绝对路径；
- `..` 父目录逃逸；
- 指向工作目录外部的符号链接；
- 非 UTF-8 文件读取。

命令工具默认拦截 `sudo`、`rm`、关机重启、磁盘管理、`git reset --hard`、强制 Git 清理或推送、`find -delete`、下载脚本后直接交给 shell 执行等明显高风险操作。

以下敏感操作在安全模式下可以使用，但必须先由用户逐次确认：

- 安装、卸载或同步 Python、JavaScript 和系统软件包；
- 使用 `curl`、`wget`、`ssh`、`scp`、`sftp` 访问外部网络；
- 执行 Git 提交、推送、拉取、获取或克隆；
- 使用 `chmod` 修改文件权限。

如果显式添加 `--allow-dangerous-commands`，原本被阻止的高风险命令也只会进入人工确认流程，不会直接执行。该参数只能由启动程序的用户提供，模型不能通过 Tool Call 自行开启。没有确认入口的程序化调用会拒绝敏感命令，默认选择始终是更安全的“不执行”。

### strict 系统沙箱

CLI 默认使用 `--sandbox-mode strict`。每条 `run_command` 都创建独立临时目录，并通过 macOS `sandbox-exec` 应用以下限制：

- 工作目录允许读取和写入；
- 该命令专属的临时目录允许读取和写入，执行结束后删除；
- 系统运行库、开发工具和 Homebrew 等标准位置只读；
- 其他位置默认不能读取文件内容，也不能写入；
- 默认禁止网络；
- 经过用户确认的联网命令只临时开放出站网络；
- 不加载 `~/.zshrc` 等用户 shell 配置；
- `HOME`、`TMPDIR` 和常见缓存目录指向命令专属临时目录；
- 使用受控 `PATH`，优先使用目标项目自己的 `.venv/bin`；
- 不把名称包含 API Key、Token、Password、Secret、Authorization 或 Credential 的环境变量传给子进程。

模型也可以在 `run_command` 中显式设置 `network_access=true`。即使命令文本没有被识别为 `curl` 等联网程序，本地 Agent 仍会先显示完整命令并请求用户确认，再只为这一条命令开放出站网络。

沙箱与原有安全策略叠加，而不是替代关系。危险命令仍会先被拦截；即使使用 `--allow-dangerous-commands` 并得到人工批准，系统沙箱仍然限制其访问范围。

### policy 兼容模式

`--sandbox-mode policy` 保留危险命令检测、人工确认、超时、进程组终止和敏感环境变量清理，但不使用系统级文件或网络隔离。它用于 `sandbox-exec` 不可用时的显式兼容，不应被描述为强沙箱。

系统沙箱仍不是虚拟机或容器。命令对授权工作目录拥有完整写权限，因此可以修改或删除项目内文件；复杂原生程序也可能利用操作系统漏洞。应继续在可恢复的项目副本中使用 Agent，并结合 Git 检查点审查重要修改。

## 已知限制

- 当前主要面向 macOS 和 `/bin/zsh`，尚未验证 Windows 与 Linux；
- strict 模式依赖 macOS `sandbox-exec`，尚未提供 Linux 或 Windows 强沙箱；
- 系统沙箱允许命令完整修改工作目录内文件，不等同于虚拟机；
- 只支持 UTF-8 文本文件，不处理图片、二进制文件和 Notebook 单元；
- `write_file` 会覆盖目标文件，项目本身不提供自动备份或回滚；
- Git 检查点可用于比较和保留快照，但当前不提供自动恢复工具；
- Git 工具要求工作目录本身是仓库根目录；
- 上下文预算按字符近似，不是精确 Token 统计；
- 语义摘要可能遗漏次要细节，失败时的确定性摘要只保留关键预览；
- 长期记忆使用本地词元相似度，不等同于神经网络 Embedding；
- 自动提取优先保证准确率，只识别明确表述，隐含偏好需用 `/remember` 保存；
- 会话凭据脱敏属于启发式识别，不能保证发现所有自定义秘密格式；
- 本地会话可能包含源代码和工具输出，需要保护会话目录；
- 流式输出只展示模型正文，不展示内部 `reasoning_content`；
- 没有自动 Git 提交、分支管理或修改回滚；
- 真实模型行为具有随机性，复杂任务仍可能失败或需要重新描述任务。
